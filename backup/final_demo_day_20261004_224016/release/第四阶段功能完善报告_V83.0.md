## 二、新增功能清单

### 任务1：邮箱预热基础版（phase4-warmup.js）

**1.1 预热配置面板**
- 选择参与预热的邮箱账户（多选checkbox，从`S.emailAccounts`读取）
- 每日预热邮件数量：滑块2-10封，默认从2封开始逐步增加
- 预热内容模板选择：4套预设模板（可编辑）
- 预热周期：14天为一个完整周期
- 配置保存到`S.warmupConfig`

**1.2 预热任务生成**
- 环形互发逻辑：A→B→C→A，按轮次偏移收件人避免同日重复配对
- 每个任务含：发件邮箱、收件邮箱、邮件主题、邮件正文、状态、日期
- 任务保存到`S.warmupTasks`，按日期分组
- 同一天不重复生成

**1.3 预热进度跟踪**
- 每个参与邮箱的预热卡片：邮箱地址、第X/14天、累计发送量、今日发送量、预热分数（0-100）
- 预热分数公式：`已完成天数/14×60 + 累计发送量/140×40`，上限100，≥80显示达标
- 彩色进度条可视化
- 完成标准：连续14天正常发送，预热分数>80

**1.4 任务清单与标记**
- 今日任务列表：发件人→收件人、主题预览、正文预览
- "复制主题"、"复制正文"按钮（剪贴板）
- "标记已完成"按钮：更新任务状态、邮箱累计发送量、今日发送量、预热分数
- 历史任务按日期分组折叠展开

**1.5 预热内容模板**
- 4套预设英文商务邮件模板：
  - Industry News Sharing（行业资讯分享）
  - Product Update（产品更新）
  - Holiday Greeting（节日问候）
  - Business Check-in（商务问候）
- 支持`{sender}`、`{recipient}`、`{date}`变量替换
- 模板可编辑保存

### 任务2：Webhook/API开放接口（server.js + phase4-api-webhook.js）

**2.1 REST API端点**（全部`x-api-key`鉴权）

| 方法 | 端点 | 说明 | 认证 |
|------|------|------|------|
| GET | `/api/v1/health` | API健康检查 | 免认证 |
| GET | `/api/v1/customers` | 客户列表（支持category/status/page/limit/search筛选） | API Key |
| GET | `/api/v1/customers/:id` | 客户详情 | API Key |
| POST | `/api/v1/customers` | 新增客户 | API Key |
| GET | `/api/v1/drafts` | 开发信草稿列表 | API Key |
| GET | `/api/v1/send-tasks` | 今日发送任务 | API Key |
| GET | `/api/v1/analytics` | 复盘统计数据 | API Key |

**2.2 API Key管理**（`x-admin-token`或已登录会话）
- 生成/撤销API Key，Key仅生成时完整返回一次，列表脱敏显示
- 每次API调用记录日志（时间、端点、apiKeyId、状态、IP、耗时）
- 限流：每个API Key每分钟最多60次调用（滑动窗口）

**2.3 Webhook功能**
- 配置Webhook URL（如飞书机器人、企业微信）
- 支持4类触发事件：
  - `customer.reply`（新客户回复）
  - `inquiry.new`（新询盘）
  - `sendtask.completed`（发送任务完成）
  - `followup.due`（跟进提醒到期）
- 触发时向URL POST JSON，含`event`、`timestamp`、`payload`、`signature`
- 签名验证：`X-Webhook-Signature = HMAC-SHA256(secret, timestamp + '.' + payload)`
- Webhook投递日志记录（时间、事件、URL、状态、响应码）
- fire-and-log投递模式，不阻塞主流程

**2.4 前端管理面板**（3个Tab）
- API Keys：列表、生成、撤销、调用日志表格、统计卡片
- Webhooks：列表、添加、测试、启停、删除、投递日志
- API文档：认证说明、端点表、curl示例、签名公式

**2.5 数据同步机制**
- 后端独立JSON文件存储（`data/`目录），与前端localStorage分离
- `POST /api/v1/admin/sync-snapshot`：前端把localStorage业务数据推给后端
- Admin token首次启动自动生成并打印到终端（环境变量`ADMIN_TOKEN`可覆盖）

### 任务3：AI生图个性化（phase4-ai-image.js）

**3.1 三种生图类型**（Tab切换）
- **公司定制图**：输入客户公司名，生成"Dear [Company], here is our new [product] collection"风格横幅
- **产品场景图**：选择品类（户外刀/厨房刀/剪刀/厨房用品），生成产品在厨房/户外场景中的图片，自动融入品类知识库卖点（Yangjiang manufacturing、OEM/ODM、D2 steel等）
- **节日问候图**：Christmas/Thanksgiving/New Year/Chinese New Year

**3.2 生图调用与故障转移**
- 三级故障转移链：
  1. `POST /api/ai/generate`（服务端模型路由）
  2. 复用现有`callAIImage`（cogview-3-flash）
  3. 本地Ollama `flux2-klein`（127.0.0.1:11434）
- 全部try/catch包裹，任一不可用自动降级，最终失败toast提示不崩溃
- 图片格式兼容：URL / base64 / data-uri 三种返回统一归一化

**3.3 尺寸选择**
- 方形(1:1)、横版(16:9)、竖版(9:16)，映射到CogView像素尺寸

**3.4 图片库（历史记录）**
- `S.aiImageHistory`存储：id、prompt、imageUrl/base64、type、category、createdAt、usedInDrafts
- 网格展示，按类型/品类筛选
- 操作：预览、复制HTML代码（`<img src="...">`）、下载、插入开发信、删除
- localStorage容量守卫：>30条截断、base64总量>3.5MB自动清理旧图并提示

**3.5 开发信编辑器集成**
- MutationObserver监听`#dr_body`抽屉，在「📚 插入品类知识」旁自动注入「🖼️ 插入AI图片」按钮
- 插入时定位textarea caret写入`<img>`标签
- 无编辑器打开时自动复制HTML到剪贴板并提示

## 三、技术架构说明

### 3.1 模块注入模式
```
app.js (原始 renderView + loadState + persist)
  → phase4-warmup.js (拦截 emailWarmup)
  → phase4-api-webhook.js (拦截 apiIntegration)
  → phase4-ai-image.js (拦截 aiImageLibrary + MutationObserver注入编辑器按钮)
  → phase4-whatsapp.js (拦截 whatsappManage)
```
每个模块采用IIFE + `NAV.push()` + `renderView`包装链注入，互不冲突。

### 3.2 数据持久化
- **前端**：12个新字段加入`loadState()`和`persist()`，localStorage存储
- **后端**：`data/`目录JSON文件存储（api_keys、api_logs、webhooks、webhook_logs、workbench_snapshot、admin_token）
- 所有新CSS class以`p4-`前缀，避免污染

### 3.3 后端API架构
- 原生Node.js `http.createServer`，零npm依赖
- 中间件链：CORS → 限流 → API Key鉴权 → 路由 → 日志
- Webhook投递：异步非阻塞，HMAC-SHA256签名

### 3.4 AI生图调用链
```
前端fetch('/api/ai/generate')
  → 失败 → callAIImage(cogview-3-flash)
    → 失败 → 本地Ollama flux2-klein
      → 失败 → toast提示用户稍后重试
```

## 七、已知问题与后续建议

### 7.1 已知问题（非阻断）
1. **API数据同步**：后端API返回的客户/草稿数据来自后端JSON快照，需前端调用`sync-snapshot`同步localStorage数据后才会有真实数据。建议在前端管理面板加"同步数据"按钮。
2. **AI生图模型可用性**：依赖cogview-3-flash或本地Ollama，若均不可用则生图功能不可用。已做三级故障转移和优雅降级。
3. **localStorage容量**：AI生图base64数据较大，已加容量守卫（3.5MB阈值），长期建议转URL托管。

### 7.2 后续建议
1. **API数据自动同步**：在前端设置定时任务，每5分钟自动同步localStorage到后端快照
2. **Webhook事件自动触发**：目前Webhook需手动调用trigger端点，建议在客户回复/询盘创建等操作时自动触发
3. **邮箱预热智能调整**：根据退信率自动调整每日发送量，退信率>1%时自动降级
4. **WhatsApp消息状态回执**：若未来接入WhatsApp Business API，可实现已送达/已读状态自动同步
5. **AI生图模板库**：积累优胜图片模板，支持一键复用和A/B测试
6. **API文档在线化**：将API文档生成为独立HTML页面，支持交互式测试（Swagger风格）

## 八、安全说明

1. **Admin Token**：首次启动自动生成，存储于`data/admin_token.json`，建议加入`.gitignore`
2. **API Key**：SHA256哈希存储，明文仅生成时返回一次
3. **Webhook签名**：HMAC-SHA256，接收方可验证来源真实性
4. **限流**：60次/分钟/Key，防止滥用
5. **CORS**：`/api/v1/*`单独放行`*`，不影响工作台同源安全策略
6. **数据隔离**：后端`data/`目录与前端localStorage分离，建议`data/`加入`.gitignore`
