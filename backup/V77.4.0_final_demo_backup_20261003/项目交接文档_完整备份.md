## 二、核心业务边界（绝对禁止）

### 工作台只负责：
1. 整理客户公司资料
2. 展示客户联系方式
3. 客户身份、重复、DNC、ICP、风险判断
4. 绑定 Knowledge Pack 和可追溯事实
5. 生成个性化开发邮件草稿（本地 AI）
6. 生成 LinkedIn / 跟进消息草稿
7. 提供人工审核、复制和本地导出能力
8. 跟进计划提醒和人工结果记录

### Leo（用户）负责：
- 审核草稿
- 在自己的邮箱、LinkedIn、WhatsApp 或其他外部渠道**人工发送**
- 如需要，可在工作台中事后记录已人工发送

### 绝对禁止：
- ❌ SMTP、sendmail、Gmail/Outlook API
- ❌ LinkedIn API、WhatsApp API
- ❌ 邮件投递 webhook、自动外部 HTTP 发送
- ❌ AI 自动将草稿变成 sent/contacted
- ❌ 自动创建真实通信记录
- ❌ 自动定时发送、自动批量发送
- ❌ 自动抓取 LinkedIn、自动添加好友
- ❌ 绕过平台限制的爬虫
- ❌ 调用真实云端 GLM/CogView/豆包 API（仅使用本地 Ollama）
- ❌ 修改项目 A（8501）、端口、Cloudflare Tunnel、启动器
- ❌ push、部署（除非用户明确要求）

### "记录已人工发送"的定位
- 仅是事后 CRM 记录动作，不得成为主要 CTA
- 不得触发任何外部请求
- 必须二次确认，填写渠道和实际发送时间
- 文案明确显示："此操作不会发送任何邮件或消息，仅记录您已在外部渠道手动发送。"

## 三、技术架构

### 后端模块（独立 JS 文件）
| 模块 | 功能 |
|------|------|
| `server.js` | HTTP 服务器、API 路由、静态文件服务 |
| `model-router.js` | 模型路由、故障转移、慢响应处理 |
| `local-model-lock.js` | 本地模型互斥锁、等待队列 |
| `model-trace.js` | 模型调用 Trace 记录（内存存储） |
| `prospect-priority.js` | 客户优先级评分算法（五维 0-100 分） |
| `website-evidence.js` | 网站证据采集（多页面、SSRF 防护） |
| `customer-import.js` | CSV 批量导入、字段映射、数据清洗、重复/DNC 检测 |

### 前端
- 单文件 `index.html`，包含所有 inline CSS 和 JavaScript
- 数据存储：浏览器 localStorage（`S` 对象）
- 无框架、无构建工具

### 本地 AI 模型
- **Ollama 版本**：0.35.0
- **默认本地模型**：qwen3.5:9b（第一本地文本模型）
- **备用本地模型**：qwen2.5:7b
- **正确参数**：`think: false`（顶层参数，不是 thinking:false），`num_ctx=8192`，`keep_alive=0`
- **普通文本自动链**：glm-4.7-flash → glm-4-flash → qwen3.5:9b → qwen2.5:7b
- **推理链**：glm-4.7-flash → qwen3.5:9b → deepseek-r1:7b
- **视觉链**：glm-4.6v-flash → qwen3.5:9b → qwen2.5vl:7b
- **生图链**：cogview-3-flash → x/flux2-klein:4b-fp4
- **Embedding**：nomic-embed-text:latest（固定，不参与故障转移）

## 九、安全与合规要点

### XSS 安全
- 所有用户输入输出必须经过 `esc()` 转义
- test_sanitize.js 9 项测试持续验证

### 密钥安全
- 导出备份时 API Key/secret/password/authorization/bearer token/cookie/webhook secret 全部替换为 `{configured: true, redacted: true}`
- 导入脱敏备份时不覆盖本机已有密钥
- Trace、日志、错误信息不得包含密钥

### 数据脱敏
- 邮箱和电话在 UI 中脱敏显示
- 生成 emailHash 和 phoneHash 用于重复检测
- 交接包、TXT、Markdown、HTML 导出不得包含密钥
- 不保存完整 prompt、thinking/reasoning 内容

### 备份恢复
- `exportAllData()` / `importAllData()` 动态导出所有 S 键
- `clearAllData()` / `resetData()` 覆盖所有集合（含 importBatches）
- 导入前预览和冲突检测，未确认不覆盖
- 导入失败原子回滚
- schemaVersion 兼容，旧数据缺字段标记 legacy 不伪造

### SSRF 防护（网站证据采集）
- 只允许 http/https
- 阻断 localhost、127.0.0.1、0.0.0.0、私有 IP、内网域名、链路本地地址
- 阻断 file://、javascript:、data:、ftp:
- 重定向目标重新校验，最大重定向 5 次
- 连接超时 10 秒，总超时 30 秒
- 响应上限 1MB，只解析 text/html
- 不执行 JS、不提交表单、不访问登录页、不下载文件
- 不保存完整 HTML，只保存 excerpt 和 contentHash

## 十二、开始新项目阶段的标准流程

每次开始新阶段时，必须执行：
1. `git status`（确认工作区状态，保留未跟踪交接文档）
2. `git log --oneline -15`（确认基线提交）
3. 检查 8080 服务是否运行，是否加载最新代码（必要时重启）
4. 检查是否有其他进程修改 index.html、server.js、相关模块和测试文件
5. 读取相关现有代码（不要凭记忆）
6. 创建任务列表跟踪进度
7. 实施 → 测试 → 验证 → 提交（只提交项目 B 源代码和测试文件）
8. 输出完整验收报告

## 十三、重要提醒

1. **客户详情页通过 `openCustomerDetail(cid)` 抽屉打开**，不是通过 `currentView='customerDetail'`（renderView 路由中没有 customerDetail）
2. **Ollama 正确参数是 `think: false`（顶层）**，不是 `thinking: false`
3. **qwen3.5:9b 是默认本地模型**，用户已明确否决将 qwen2.5:7b 改为默认
4. **普通草稿 UI 不显示 deepseek-r1:7b、qwen2.5vl:7b、doubao-seed-2-1-turbo**，这些保留给专用任务
5. **Trace 仅保存在服务内存中**，服务重启后不可读取，UI 显示安全空状态
6. **approved 不等于已发送**，needs_review 不计入已联系，只有 manually_sent 才计入已人工发送
7. **reviewed 证据只能作为评估依据**，不能自动变成 confirmed Fact 或自动进入公开 Knowledge Pack
8. **导入预览阶段不修改正式数据**，必须 Leo 明确确认后才写入
9. **浏览器视口可能很小**（如 219x915），导航折叠时通过 JS 设置 currentView 切换页面
10. **8080 服务重启命令**：`kill <PID> && cd 项目目录 && nohup node server.js > /tmp/server_8080.log 2>&1 &`
