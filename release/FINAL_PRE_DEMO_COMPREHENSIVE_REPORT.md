### 2.2 已修复的严重问题

#### 🔴 P0-1: gpt-5.6-terra 模型路由错误
- **位置**：model-router.js:44-47
- **问题**：`api_config.json` 配置了 `gpt-5.6-terra` 为主模型，但 `OPENAI_PROXY_MODELS` 集合中没有它，导致 `getModelProvider()` 兜底返回 `glm`，请求被错误发到智谱端点，返回 `400 模型不存在(code 1211)`
- **修复**：将 `OPENAI_PROXY_MODELS` 更新为 wawapi.top 中转站真实支持的8个模型：`gpt-5.5, gpt-5.6-sol, gpt-5.6-terra, gpt-6-astra, gpt-6-sol, gpt-6-luna, gpt-6.1-sol, codex-auto-review`
- **验证**：手动调用 `gpt-5.6-terra` 成功返回 "Hello"（修复前返回400错误）

#### 🔴 P0-2: 自动故障转移链路前两跳必然404
- **位置**：model-router.js:30-32
- **问题**：`MODEL_CHAINS.text/reasoning/vision` 均以 `gpt-4o` 开头，但 wawapi 中转站**根本不提供** gpt-4o 系列（实测返回 404 `model_not_available`）。自动模式每次白跑2次404（约1.3秒）才落到 glm-4-flash，付费模型从不被使用
- **修复**：所有链路首跳从 `gpt-4o` 改为 `gpt-5.6-terra`
- **验证**：自动模式现在第1次尝试（gpt-5.6-terra）即成功，`attempt:1, failover:false`（修复前需 attempt:3）

#### 🔴 P0-3: 手动模型切换器包含5个"空气模型"
- **位置**：app.js:40531
- **问题**：下拉列表包含 `gpt-4o, gpt-4o-mini, gpt-4-turbo, claude-3-5-sonnet, gemini-2.0-flash`，这些模型在中转站均不存在。手动选中后因手动模式关闭故障转移，会直接报错
- **修复**：更新为真实可用模型列表：`gpt-5.6-terra, gpt-5.5, gpt-6-astra, glm-4-flash, glm-4.7-flash, qwen3.5:9b, deepseek-r1:7b, qwen2.5:7b`

### 3.2 已修复的前端Bug

#### 🐛 Bug-1: 开发任务页模板字符串未求值
- **位置**：app.js:12301
- **问题**：在模板字面量（`${}`语法）中错误使用了字符串拼接（`' + Math.max(0, ...) + '`），导致页面显示原始代码文本 `+ Math.max(0,` 而非计算结果
- **修复**：`' + Math.max(0, weekTarget.customers - weekNewCustomers) + '` → `${Math.max(0, weekTarget.customers - weekNewCustomers)}`
- **验证**：代码级确认，语法检查通过

#### 🐛 Bug-2: 业绩战报页市场优先级显示NaN
- **位置**：app.js:20689
- **问题**：`'★'*(5-i)` — JavaScript中字符串乘数字返回NaN，导致星级显示为"NaN"
- **修复**：`'★'*(5-i)` → `'★'.repeat(Math.max(0,5-i))`，同时添加 `(PROSPECT_KB.markets||[])` 和 `(m.name||'未知')` 空值守卫
- **验证**：代码级确认，语法检查通过

#### 🐛 Bug-3: 操作日志页多条错误记录
- **位置**：操作日志数据
- **分析**：经核查，这些"错误"记录是之前模型路由错误（gpt-5.6-terra被错发到GLM返回400）产生的真实日志条目。模型路由修复后，新的AI调用不会再产生此类错误。历史错误记录保留在日志中是正常行为（操作日志应记录真实发生的事件）
- **结论**：非代码bug，是P0-1修复前产生的历史数据
