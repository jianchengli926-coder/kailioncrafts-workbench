## 四、功能详细说明

### P1-1 开发信质量检查器（12项检查）

1. **硬阻断状态检查**: DNC、suppressed、disqualified、closed
2. **有效收件邮箱**: 格式校验 + 非空
3. **未确认Fact引用**: 检查引用的knowledgeFact是否为confirmed状态
4. **机密内容检测**: confidential、internal、内部价格等关键词
5. **未经证实事实**: MOQ、价格、交期、产能、认证、客户案例（未在知识库中确认）
6. **敏感信息**: API Key、密码、Token、内部成本
7. **CTA检查**: 是否包含明确的行动召唤
8. **长度检查**: 过短(<50词)或过长(>300词)
9. **XSS/注入检测**: 危险HTML、script标签、事件属性
10. **个性化证据**: 是否引用了客户特定证据（网站、产品、新闻）
11. **已归档Knowledge Pack**: 引用的pack是否已归档
12. **重复草稿/触达**: 同一客户近期是否已有相似草稿

**门控规则**:
- 硬阻断问题: 不允许进入 reviewed_ready，markDraftReviewed时弹confirm警告
- 中风险问题: 允许进入人工审核队列，显示醒目警告
- 低风险问题: 只显示建议，不阻塞

**集成位置**: 草稿列表质量列、草稿编辑器质量面板（自动检查，24小时过期重检）、审核队列质量列、批量质检按钮

### P1-2 线索/邮箱质量评分（11项检查）

1. 邮箱基础格式校验
2. 域名存在性检查
3. DNS/MX记录查询（Node.js内置dns模块，免费）
4. free mailbox / corporate mailbox 分类
5. disposable 邮箱特征识别
6. role 邮箱识别（info@、sales@、contact@等）
7. 网站URL有效性
8. 公司名/国家/买家类型/职位完整度
9. 证据新鲜度（30天内/90天内/过期）
10. DNC/重复/黑名单/状态异常
11. 多渠道联系方式（LinkedIn/电话/其他）

**MX查询策略**:
- 启用DNS/MX查询，使用Node.js内置dns模块（免费）
- 不在每次输入时同步强制查询
- 客户导入后进入检查队列，并发=3
- 高优先级(A级)客户优先检查
- 24小时缓存
- 查询超时或失败标记 pending/unknown，不误判为 invalid
- 重试记录 retryCount、lastError、nextRetryAt
- 不调用付费邮箱验证 API

**集成位置**: 客户表质量列、批量评分按钮、CSV导入后自动异步评分

### P1-3 Campaign Task 队列增强

**新增任务状态**: pending → running → succeeded/failed/retry_scheduled → overdue/blocked

**重试规则**:
- 临时错误可重试: timeout、429、5xx、connection_refused、network_error
- 指数退避: 1分钟 → 5分钟 → 15分钟
- 配置错误不自动重试: 400、401、403、422、invalid_api_key
- 最大重试次数: 3次
- 手动模型失败不得切换其他模型

**任务历史**: 每次状态变化写入 taskHistory（时间、从什么状态、到什么状态、操作者、动作、备注），最多50条

**逾期检测**: dueAt过期自动标记overdue，进入今日工作提醒

**集成位置**: 今日工作页面异常任务提醒（逾期/失败/待重试）、任务详情韧性面板、手动重试按钮

### P2-1 首次响应 SLA 计时

**默认SLA**:
- 高优先级询盘: 60分钟
- 普通询盘: 240分钟
- 客户回复: 240分钟

**SLA状态**: on_track（正常）→ due_soon（剩余<25%）→ breached（已超时）→ met（已响应）

**非工作时间**: 只记录，不自动判定违约（周一至周五9:00-18:00为工作时间）

**集成位置**: 询盘列表SLA列、询盘详情SLA面板、"标记已响应"按钮、数据看板
