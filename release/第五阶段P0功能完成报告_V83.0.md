## 二、8项功能详细说明

### 功能1：询盘邮件AI自动分类+意向评级视图

**导航入口**: 🏷️ AI分类评级

**功能描述**:
- 对AI收件箱（S.inbox）中的每封客户回复自动分类
- 分类维度：意向等级（高/中/低）、类型（询价/索样/问交期/问认证/投诉/其他）、紧急度（高/中/低）
- AI调用使用 gpt-5.6-terra，temperature 0.2
- 分类结果写入 inbox.aiClassification，同步到客户档案（customer.aiIntent）和时间线

**页面结构**:
- 顶部统计卡片：高/中/低意向数量、未分类数量
- 筛选栏：按意向等级 + 按类型双重筛选
- "🤖 AI批量分类"按钮：一键分类所有未分类邮件
- 单条"重新分类"按钮
- 列表按高→中→低→未分类排序，高意向置顶

**使用方法**:
1. 进入「🏷️ AI分类评级」页面
2. 点击「🤖 AI批量分类」对所有未分类邮件进行分类
3. 使用筛选栏查看特定意向等级或类型的客户
4. 点击客户名可跳转查看详情
5. 对分类不准的邮件点击「重新分类」

### 功能2：AI主动行动建议

**导航入口**: 💡 AI行动建议

**功能描述**:
- 纯规则引擎（不消耗AI token），基于当前数据自动生成可执行建议
- 5条规则：
  1. **高意向未跟进**：highIntent=true 或 dynamicIntentScore≥70 且状态非已回复 → 建议优先联系
  2. **超7天无回复**：最后发送超过7天且无回复 → 建议发送跟进邮件
  3. **高打开未回复**：打开邮件≥3次但未回复 → 建议电话跟进
  4. **邮箱配额预警**：今日发送量接近上限（剩≤1封）→ 提醒配额
  5. **待审核草稿**：有状态为"待检查"的开发信 → 提醒审核

**页面结构**:
- 顶部："🔄 刷新建议"按钮 + 上次生成时间
- 建议卡片按优先级（high→medium→low）排序
- 每张卡片：图标+标题+详情+关联客户+「立即处理」按钮（一键跳转）+「忽略」按钮
- 自动生成：进入页面时如超过4小时未生成则自动刷新
- 每天生成一次，手动刷新可强制重建

**使用方法**:
1. 进入「💡 AI行动建议」页面
2. 系统自动分析数据并生成建议列表
3. 点击「立即处理」跳转到对应功能页面（客户台账/发送历史/今日发送/开发信）
4. 处理完的建议可点「忽略」移除
5. 建议每天自动更新，也可手动点「🔄 刷新建议」

### 功能3：AI决策审计日志

**导航入口**: 🔍 AI决策审计

**功能描述**:
- 记录所有AI生成内容的人工审核过程，把"人工审核门控"做成产品亮点
- 自动捕获：5秒轮询扫描新生成的 drafts / replyDrafts / wakeupDrafts，自动创建"待审核"审计记录
- 手动录入：提供「📝 记录AI输出」按钮手动添加
- 审核操作：通过✅ / 修改后通过✏️（带修改说明）/ 拒绝❌（带拒绝原因）/ 标记发送时间

**统计维度**:
- 总记录数、AI通过率、平均修改率、拒绝数
- 按内容类型筛选（开发信/AI回复/唤醒话术）
- 按审核状态筛选（待审核/已通过/已修改/已拒绝）
- 点击展开详情：AI原文 vs 修改后内容对比

**暴露的全局函数**:
- `window.p5LogAudit({contentType, customerId, customerName, aiOutput, model})` — 创建审计记录
- `window.p5UpdateAudit(id, {humanAction, modifiedContent, changeSummary, rejectedReason, sentAt})` — 更新审核状态

**使用方法**:
1. 进入「🔍 AI决策审计」页面
2. 新生成的开发信/回复草稿会在5秒内自动出现在列表中（状态：⏳待审核）
3. 点击记录展开详情，查看AI生成的完整内容
4. 选择操作：
   - 「通过」：内容无需修改，直接通过
   - 「修改后通过」：填写修改说明，记录修改前后对比
   - 「拒绝」：填写拒绝原因
   - 「标记已发送」：记录最终发送时间
5. 顶部统计卡片实时显示通过率、修改率等指标

### 功能4：BANT/承诺/异议结构化抽取

**导航入口**: 🏷️ AI分类评级 → 📊 BANT洞察 Tab

**功能描述**:
- AI分析客户回复邮件，自动抽取结构化销售信息
- **BANT四维度**：
  - Budget（预算）：客户提及的预算范围或采购金额
  - Authority（决策权）：客户的决策角色和权限
  - Need（需求）：客户明确表达的产品需求
  - Timeline（时间线）：客户期望的采购或交付时间
- **承诺**：客户做出的明确承诺（如"下周确认订单"）
- **异议**：客户提出的顾虑（价格高/交期长/认证不全等），可标记已解决

**数据写入**:
- customer.bant = {budget, authority, need, timeline, extractedAt}
- customer.commitments = [{id, text, createdAt, status: pending/fulfilled/broken}]
- customer.objections = [{id, text, type, createdAt, resolved}]

**使用方法**:
1. 进入「🏷️ AI分类评级」页面
2. 切换到「📊 BANT洞察」Tab
3. 列表显示所有已抽取BANT数据的客户
4. 点击客户展开4维BANT卡片 + 承诺列表 + 异议列表
5. 承诺可标记「已兑现/未兑现」，异议可标记「已解决」
6. 点「🔍 重新抽取」对该客户重新进行AI分析
7. BANT抽取在AI分类时同步触发，无需单独操作

### 功能5：开发信质检增强

**入口**: 开发信管理页面 → 每封草稿的质检面板下方自动追加

**功能描述**:
在现有12项质检基础上，增加5项增强检测：

| 检测项 | 评分逻辑 | 通过标准 |
|--------|----------|----------|
| **个性化程度** | 公司名+25/人名+20/产品名+20/行业+15/国家+10/细节+10 | ≥70分通过，40-70警告，<40不通过 |
| **长度建议** | 统计英文单词数，B2B最佳80-120词 | 80-120通过，60-80/120-150警告，<60/>150不通过 |
| **标题钩子** | 数字+25/问题+20/个性化+25/价值主张+20/紧迫感+10 | ≥60通过，30-60警告，<30不通过 |
| **CTA检测** | 检测reply/respond/catalog/sample/quote等行动号召词 | 有明确CTA通过，无则不通过，过强则警告 |
| **垃圾词检测** | 检测free/guarantee/100%/best price等15个触发词 | 0个通过，1-2个警告，≥3个不通过 |

**综合评分**: 原质检60% + 增强5项40%，等级A/B/C/D

**自动挂载**: 在开发信草稿页面点击「质检」后，原12项面板下方自动出现「🚀 P5 增强质检」彩色面板

**暴露的全局函数**:
- `window.p5EnhancedQualityCheck(draft, context)` — 运行增强质检
- `window.p5RenderEnhancedPanel(report)` — 渲染增强质检面板

**使用方法**:
1. 进入「✉️ 开发信」页面
2. 点击任意草稿的「质检」按钮
3. 原12项质检结果下方自动显示「🚀 P5 增强质检」面板
4. 5项检测分别显示绿/黄/红状态
5. 点击每项可展开查看详细命中情况（如具体哪些垃圾词被命中）
6. 综合评分和等级大字显示，作为发送前的参考

### 功能6：ICP行为信号动态修正

**导航入口**: 🏷️ AI分类评级 → 📈 行为信号 Tab

**功能描述**:
客户意向评分不再是静态的，根据客户行为动态调整：

| 行为信号 | 分值 | 触发条件 |
|----------|------|----------|
| 秒回（<1小时） | +2 | 客户回复时间 - 发送时间 < 1小时 |
| 索要报价 | +3 | 回复含 price/quote/cost/报价/价格 |
| 索要样品 | +3 | 回复含 sample/样品 |
| 提及竞品 | +2 | 回复含 competitor/brand/其他品牌名 |
| 问交期 | +1 | 回复含 delivery/lead time/交期 |
| 问认证 | +1 | 回复含 certificate/CE/BSCI/ISO/认证 |
| 打开邮件3次+ | +1 | sendRecords中该客户打开次数≥3 |
| 点击链接 | +2 | sendRecords中该客户有点击记录 |
| 超7天无回复 | -1 | 最后发送超过7天且无回复 |
| 退订/拒绝 | -5 | 状态为"不再联系"或回复含unsubscribe |

**动态意向分** = 基础分（leadScore或scores.total，默认50）+ 所有行为信号分值，clamp到0-100
**高意向标记**: dynamicIntentScore ≥ 70 自动设置 customer.highIntent = true

**使用方法**:
1. 进入「🏷️ AI分类评级」页面
2. 切换到「📈 行为信号」Tab
3. 列表按动态意向分从高到低排序，高意向（≥70）金色高亮
4. 点击客户展开行为信号历史时间线，显示每个信号的类型、分值、描述和时间
5. 点击「🔄 重新扫描所有信号」对全部客户重新检测
6. 行为信号在AI分类完成后自动触发更新
7. 高意向客户会在「💡 AI行动建议」中优先推荐

### 功能7：飞书每日播报（Webhook定时推送）

**导航入口**: 📢 飞书播报

**功能描述**:
- 利用飞书自定义机器人Webhook，每日固定时间推送工作台数据汇总到飞书群
- 推送内容（5项独立开关）：
  1. 今日待发送任务数
  2. 昨日发送量/打开率/回复率
  3. 待跟进客户数
  4. 高意向未跟进客户（列出前3个）
  5. AI行动建议Top 3
- 飞书消息卡片格式（interactive card），蓝色主题

**服务端**: `POST /api/feishu/send` 代理端点，用Node内置https模块转发，避免浏览器CORS问题

**定时策略**: 页面打开时每分钟检查是否到达推送时间，到达且今天未推送则自动推送（需保持工作台页面打开）

**使用方法**:
1. 在飞书群中添加「自定义机器人」，获取Webhook URL（格式：https://open.feishu.cn/open-apis/bot/v2/hook/xxx）
2. 进入「📢 飞书播报」页面
3. 粘贴Webhook URL，设置推送时间（默认09:00）
4. 开启「启用定时推送」开关
5. 按需勾选/取消5项推送内容
6. 点击「💾 保存配置」
7. 点击「🧪 立即推送测试」验证飞书群是否收到消息
8. 推送历史显示最近10次记录（时间/成功/失败原因）
9. **注意**：需保持工作台浏览器页面打开才能定时推送

### 功能8：WhatsApp 24h/72h合规提醒

**导航入口**: ⏰ WA合规提醒

**功能描述**:
- WhatsApp Business API规则：客户主动发起消息后24小时内可免费回复，超过24小时需使用模板消息
- 实时计算每个客户的24小时回复窗口剩余时间

**合规状态**:
| 状态 | 条件 | 颜色 | 建议操作 |
|------|------|------|----------|
| 🟢 活跃 | 剩余>4小时 | 绿色 | 可直接发送消息 |
| 🟡 即将过期 | 剩余0-4小时 | 黄色 | 尽快回复 |
| 🔴 已过期 | 超过24小时 | 红色 | 需使用模板消息 |
| ⚪ 冷却 | 超过72小时 | 灰色 | 建议冷却后再联系 |

**使用方法**:
1. 进入「⏰ WA合规提醒」页面
2. 顶部统计：24h窗口内/即将过期/已过期/72h冷却的客户数
3. 客户列表按紧急程度排序（即将过期→已过期→窗口内→冷却）
4. 每条显示：客户名、电话、最后消息时间、剩余窗口倒计时、状态标签
5. 操作按钮：
   - 🟢窗口内：「💬 发送消息」打开wa.me（手动发送）+「📋 复制消息」
   - 🔴已过期：弹窗警告"已超过24h免费窗口，建议使用模板消息"，确认后打开wa.me
   - ⚪冷却：「⏳ 标记冷却」设置客户冷却状态
6. 页面每60秒自动刷新倒计时
7. 暴露 `window.p5CheckWACompliance(customerId)` 供其他模块调用

## 六、已知限制与后续建议

### 当前限制
1. **飞书定时推送**：需保持工作台页面打开，关闭浏览器后不会推送（纯前端定时方案）
2. **AI分类**：需要收件箱中有客户回复数据，空数据时页面显示引导文案
3. **审计日志自动捕获**：通过5秒轮询实现，新生成的草稿最多5秒后出现在审计列表
4. **浏览器验证**：本次通过Node.js vm环境冒烟测试验证，建议Leo在实际浏览器中逐一操作确认

### 后续可优化方向
