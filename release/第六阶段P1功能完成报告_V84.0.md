### F9：自动跟进序列 + 条件分支（Day1/3/7/14）

**导航入口**：左侧 🔄 跟进序列 → [序列管理] Tab

**核心能力**：
- 默认4步序列模板：Day1首封 → Day3跟进 → Day7再跟进 → Day14最后通牒
- 模板可编辑：每步天数、标签、AI生成的话术模板
- 每客户仅一个活跃序列，记录当前步数、开始日期、每步到期日
- **条件分支**（打开看板或标记完成时自动判定）：
  - 客户已回复 → 序列停止，标记 completed
  - 客户退订/黑名单 → 序列停止，标记 cooldown
  - 邮件已打开未回复 → 使用 "opened-not-replied" 话术变体
  - 邮件未打开 → 使用 "not-opened" 话术变体
- AI基于知识库（公司事实、产品品类）生成每步英文跟进草稿
- 进度可视化：已完成绿色 / 当前蓝色 / 未来灰色

**硬约束**：只生成草稿和任务提醒，**绝不自动发送**。

### F10：客户背调 AI 一页纸摘要

**导航入口**：左侧 🔍 客户背调 → [背调一页纸] Tab

**核心能力**：
- AI生成5段结构化背调：
  1. **公司概况**：行业、规模估算、市场区域、官网
  2. **决策人**：姓名、职位、背景线索、LinkedIn
  3. **采购信号**：是否采购同类产品（结合网站证据采集）
  4. **竞争态势**：当前供应商/竞品推测（强制标注"AI推测，需验证"）
  5. **切入建议**：最有效的沟通角度（2-3句）
- 结果存入客户档案 `c.p6Briefing`，可随时刷新
- 一页纸卡片格式，支持打印（`window.print()` + `@media print`）
- 背调历史记录在 `S.p6BriefingHistory`

### F11：客户 A/B/C 分级与差异化跟进策略

**导航入口**：左侧 🔄 跟进序列 → [客户分级] Tab

**分级算法**（加权综合）：
| 维度 | 权重 | 数据来源 |
|---|---|---|
| 线索质量分 | 40% | `leadScore` / `scores.total` |
| 行为/动态意向 | 30% | `dynamicIntentScore` / `behaviorSignals` |
| BANT信息 | 20% | BANT抽取结果（第五阶段） |
| 客户类型/来源 | 10% | `customerType` / `source` |

**分级标准**：
- **A级（≥75分）**：高意向高价值 → 每周跟进，邮件+WhatsApp+电话多渠道
- **B级（50-74分）**：有潜力 → 每两周跟进，邮件为主
- **C级（<50分）**：待培育 → 每月触达，内容营销为主

**操作**：
- 顶部A/B/C分布统计卡
- 客户表按分级排序，支持手动下拉改级
- 手动改级后，AI异步推荐差异化跟进策略

### F13：发送前 Deliverability 体检（SPF/DKIM/DMARC）

**导航入口**：左侧 📬 送达体检 → [送达体检] Tab

**核心能力**：
- 对每个邮箱账户的域名执行4项DNS检查：
  - **SPF**：TXT记录查询，检测 `v=spf1`
  - **DKIM**：尝试7个常用selector（google/default/selector1/selector2/mail/k1/s1），检测 `v=DKIM1` 或 `p=`
  - **DMARC**：`_dmarc.` 前缀TXT查询，检测策略 p=none/quarantine/reject
  - **黑名单**：MX记录IP反查 Spamhaus / Spamcop DNSBL
- 结果红/黄/绿三色标识，每项附修复建议
- 整体评分 0-100，overall pass/warn/fail
- "一键检查全部账户"，账户间500ms间隔防DNS限流
- 暴露 `window.p6GetAccountHealth(emailAccountId)` 供其他模块调用

**后端API**：`POST /api/deliverability/check`
- 并行查询（SPF/DMARC/MX同时），DKIM selector分批并行
- 单查询3秒超时，整体15秒超时
- 实测响应：~0.05秒（kailioncrafts.com）

### F16：渠道 Fallback 建议（邮件无回复→WhatsApp）

**导航入口**：左侧 🔄 跟进序列 → [渠道Fallback] Tab

**触发规则**：
| 触发条件 | 建议渠道 | 理由 |
|---|---|---|
| 邮件发送7天未打开 | WhatsApp | 邮件可能进垃圾箱，换渠道触达 |
| 邮件打开3次但未回复 | 电话 | 有兴趣但犹豫，需直接沟通 |
| WhatsApp已读48h未回 | 邮件发正式报价 | 非正式渠道已触达，转正式报价 |
| 多渠道14天无响应 | 沉睡唤醒 | 进入沉睡客户唤醒流程 |

**操作**：
- "扫描全部客户生成建议"按钮，自动按 customer+trigger 去重
- 每条建议一键跳转到对应渠道消息生成页面（带customer参数）
- 可忽略单条建议
- 建议存入 `S.p6FallbackSuggestions`

### F17：线索评分 Trace（为什么这么评）

**导航入口**：左侧 🔍 客户背调 → [评分溯源] Tab

**评分拆解**：
| 类别 | 项目 | 分值 |
|---|---|---|
| **基础分** | 客户类型（进口商/品牌商25，电商20，零售15，其他10）+ 市场分（美/德/英/澳+10，其他发达+5） | 0-35 |
| **加分项** | 有官网+10、LinkedIn+5、决策人明确+10、WhatsApp+5、品类明确+5 | 0-35 |
| **行为分** | 邮件打开+5（上限15）、链接点击+8（上限16）、24h快回+15、收到回复+20 | 0-66 |
| **扣分项** | 免费邮箱-10、临时域名-15、30天无互动-10、退订-20 | 0-55 |

- 最终分 = 基础+加分+行为-扣分，封顶0-100
- 等级：≥80=A、≥60=B、≥40=C、其他=D
- 每项显示具体数值和说明
- 评分变化历史：`c.p6ScoreHistory = [{date, score, reason}]`，仅分数变化时追加
- "重新计算"按钮强制重算并记录历史

### F18：AI 沟通质检（检测业务员回复质量）

**导航入口**：左侧 📊 质检与分析 → [回复质检] Tab

**6维度评分**（AI + 系统混合）：
1. **问题覆盖**：是否回应了客户所有问题（AI判断）
2. **价值主张**：是否包含产品卖点（AI判断）
3. **CTA**：是否有明确行动号召（AI判断）
4. **语气**：是否专业友好（AI判断）
5. **语法**：拼写/语法错误（AI判断）
6. **响应时效**：≤24h=pass，24-48h=warn，>48h=fail（系统计算）

**输出**：
- 总分 0-100，6维度进度条
- 优点列表 + 改进建议列表
- 质检仪表盘：平均分、四级分布（优秀≥85/良好70-84/待改进50-69/较差<50）、TOP5高频改进建议、最近10次趋势
- "Audit All"扫描所有已发送回复草稿，"Re-audit"单条重检
- 结果存入 `S.p6ReplyQualityAudits`

**注意**：这是质检**用户的回复**，不是自动回复。

### F19：沉睡客户 AI 预测优先级

**导航入口**：左侧 📊 质检与分析 → [沉睡预测] Tab

**预测因素**：
- 历史互动频率（timeline事件数）
- 最后回复内容（inbox最近一条）
- 客户行业 / 产品品类匹配度
- 沉睡天数
- 历史响应速度

**输出**：
- 优先级：high / medium / low + 0-100分
- 预测理由（reason）
- 推荐唤醒策略：new_value（新价值）/ light_touch（轻触达）/ final_ultimatum（最后通牒）
- 策略详情（strategyDetail）
- 按优先级 → 分数降序排列
- "Predict All"批量预测，显示进度
- "生成唤醒话术"仅生成英文草稿存入 `d.p6WakeDraft`，**不发送**
- 结果反馈：已联系/已回复/无回应，附模型反馈备注

### F20：开发信漏斗全链路分析

**导航入口**：左侧 📊 质检与分析 → [漏斗分析] Tab

**8阶段漏斗**：
```
发送 → 送达 → 打开 → 点击 → 回复 → 询盘 → 报价 → 成交
```

每阶段显示：数量、从上阶段转化率、流失率。

**3维度切换**：
- 按产品品类（户外刀/厨房刀/剪刀/厨房用品）
- 按邮箱账号
- 按近6个月

**AI优化建议**（规则引擎，秒出）：
- 打开率<20% → 优化邮件标题
- 点击率<10% → 优化CTA和链接位置
- 回复率<5% → 优化正文价值主张和个性化
- 询盘率低 → 优化报价引导
- 成交率低 → 优化跟进和谈判流程

**下钻**：点击任意阶段显示该阶段客户列表。
**零数据**：显示"暂无数据"，**绝不编造数字**。

## 七、已知限制与后续优化

1. **DKIM selector**：仅尝试7个常用selector，Zoho等小众服务商的selector可能未覆盖（可在API参数中自定义）
2. **DNSBL黑名单**：仅检查Spamhaus和Spamcop，部分IP可能误报（共享IP场景）
3. **客户详情页"查看完整时间线"链接**：受"只新建模块文件"约束未在app.js中添加入口链接，但接收端已完整实现，调用 `go('customerIntel', {customerId, tab:'timeline'})` 即可
4. **AI生成质量**：背调/质检/预测依赖AI模型输出，建议用gpt-5.6-terra获得最佳效果
5. **漏斗数据**：基于真实录入数据，初期数据少时部分阶段为0，属正常现象
