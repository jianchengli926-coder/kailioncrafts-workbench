## 三、常见问题应急方案

### 问题 1：某个页面白屏或加载不出来
**应急**：按 `Cmd+R` 刷新页面。如果仍白屏，点击侧边栏其他导航项再切回来。
**预防**：演示前按检查清单逐页确认。

### 问题 2：点击按钮没反应
**可能原因**：该功能是规划中功能（会显示"即将上线"提示），或者按钮需要先选中数据。
**应急**：笑着说"这个功能正在开发中，目前是占位"，然后继续下一个演示点。
**预防**：按本手册的"点什么"操作，避开"不要点"的区域。

### 问题 3：模型不响应 / AI 生成超时
**应急**：
1. 检查网络连接（在线模型）
2. 检查 Ollama 是否运行（本地模型）：终端 `ollama ps`
3. 在设置页切换到另一个模型
4. 说"模型偶尔会超时，系统有自动故障转移，会切到下一个可用模型"
**预防**：演示前确认至少一个模型可用（在线 GLM 或本地 Ollama）。

### 问题 4：批量评分/质检卡住
**应急**：等待 10-15 秒（DNS 查询需要时间）。如果超过 30 秒，刷新页面。
**预防**：演示前先运行一次批量评分，结果会缓存。

### 问题 5：浏览器控制台报错
**应急**：不影响演示的话忽略。如果影响功能，刷新页面。
**预防**：演示前检查确认 0 控制台错误（已通过自动化测试验证）。

### 问题 6：忘记密码
**应急**：密码存在 `access_config.json` 的 passwordHash 中。如忘记，可在项目目录运行 `node -e "const c=require('./access_config.json'); console.log(c.password||'hash模式，需重置')"` 查看是否有明文密码。
**预防**：演示前确认记得密码。

### 问题 7：端口 8080 被占用
**应急**：关闭占用 8080 的程序，或修改 start.command 中的端口号。
**预防**：演示前关闭其他可能占用 8080 的服务。

## 六、启动和登录步骤（精确）

### 启动
1. 打开 Finder → 桌面
2. 双击 **`启动外贸客户开发工作台.command`**
3. 终端窗口弹出，显示启动日志
4. 等待出现 `Server running at http://0.0.0.0:8080`
5. **不要关闭终端窗口**（关闭会停止服务器）

### 登录
1. 打开 Chrome（推荐）或 Safari
2. 地址栏输入 `http://127.0.0.1:8080`
3. 页面显示登录遮罩，输入密码
4. 点击登录按钮
5. 进入数据看板，开始演示

### 局域网演示（如朋友用自己的设备看）
1. 确认 Mac 和朋友设备在同一 WiFi
2. 查看 Mac 的局域网 IP：系统设置 → Wi-Fi → 详细信息 → IP 地址（如 192.168.1.100）
3. 朋友设备浏览器访问 `http://<Mac的IP>:8080`
4. 输入同一密码登录

### 停止服务
- 演示结束后，关闭终端窗口即可停止服务
- 或在终端按 `Ctrl+C`

## 七、演示话术要点

1. **强调本地优先**：数据在自己电脑上，不上传云端，客户数据安全
2. **强调 AI 辅助开发**：整个工作台是用 AI 辅助开发的，原生 JS + Node.js，无大型框架
3. **强调证据驱动**：每个客户都有网站证据采集，开发信必须引用真实证据
4. **强调人工审核**：工作台不会自动发送邮件，所有草稿必须人工审核
5. **强调免费**：MX 查询用 Node.js 内置 DNS 模块，模型用免费在线 API 或本地 Ollama，不烧钱
6. **强调外贸场景**：SLA 首次响应、线索质量评分、开发信质量检查都是外贸 B2B 真实痛点
