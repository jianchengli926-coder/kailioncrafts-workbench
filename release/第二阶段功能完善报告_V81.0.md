## 二、新增功能清单

### 任务1：多邮箱账户管理
- 设置页"安全设置"之后新增"📧 邮箱账户管理"模块
- 支持添加/编辑/删除最多3个企业邮箱账户
- 字段：显示名称、邮箱地址、SMTP服务器、端口、授权码（password type）、每日发送上限（默认5）
- 每个账户卡片显示：今日已发数/上限、累计发送数、状态（正常/已满/未配置）
- 数据存 `S.emailAccounts`，持久化到 localStorage
- **仅配置管理，不调用SMTP发送**

### 任务2：每日发送任务清单
- 新增导航项"📮 今日发送"（key: `dailySend`），位于"开发信"之后
- 自动从客户库筛选有邮箱、有品类、未发送/未拉黑的客户
- 按四大品类均衡分配（每品类3-4封），全天最多15个任务
- 每个任务卡片显示：客户名称、邮箱、品类标签、对应开发信状态、分配邮箱、操作按钮
- 支持：✅标记已发送、跳过、替换同品类客户、查看草稿、去生成
- 顶部配额可视化：今日已发X/15 + 每个邮箱已发Y/5

### 任务3：发送量控制与配额管理
- 每个邮箱账户有 `dailySentCount` 和 `dailySentDate`
- 新的一天自动重置计数器（`p2ResetDailyCounters()`）
- 达到5封上限后该邮箱不再分配新任务，UI显示"今日已满"
- 全天15封硬上限
- 品类分布统计：户外刀/厨房刀/剪刀/厨房用品各发了多少

### 任务4：邮件打开/点击追踪（像素追踪）
- 后端 `GET /api/track/open/:token` — 返回1x1透明GIF（42字节），记录打开事件（公开路由）
- 后端 `GET /api/track/click/:token?url=xxx` — 302重定向到原始URL，记录点击事件（公开路由）
- 后端 `POST /api/track/token` — 认证路由，生成追踪token（`crypto.randomBytes(16).hex`）
- 后端 `GET /api/track/events?customerId=xxx` — 认证路由，查询客户追踪事件
- 前端生成开发信时自动：
  - 调用后端获取追踪token
  - 将正文中的 http/https 链接重写为 `https://prospect.kailioncrafts.com/api/track/click/{token}?url={encodedUrl}`
  - 在正文末尾嵌入 `<img src=".../api/track/open/{token}" width="1" height="1">` 像素
- 追踪数据存服务器端 `tracking_data.json`

### 任务5：发送记录与状态跟踪
- `S.sendRecords` 存储每条发送记录：客户、邮箱、使用账户、发送时间、草稿ID、主题、品类、打开/点击状态
- 新增导航项"📜 发送历史"（key: `sendHistory`）
- 支持按日期/邮箱/品类筛选，表格展示
- 开发复盘页面新增"发送追踪"统计卡片：累计发送、今日发送、打开率、点击率、待跟进提醒
- 客户时间线记录发送事件（复用 `addTimelineEvent`）

### 任务6：跟进提醒序列
- 客户标记已发送后，自动创建3条跟进提醒：
  - 第3天：第一封跟进
  - 第7天：第二封跟进
  - 第14天：最后跟进/冷却
- 每条提醒含：客户信息、上一封主题、建议跟进话术、到期日期
- "今日工作"页面新增"📅 今日跟进提醒"区块
- 支持复制建议话术、标记已完成
- 数据存 `S.followUpReminders`

## 三、每日发送任务分配逻辑

```
1. 筛选 eligible 客户：
   - 有主邮箱（contact.email 或 emails[0]）
   - 有 productCategory（标准化后属于4大品类之一）
   - 未拉黑（blacklisted=false）
   - 未退订（unsubscribe=false）
   - 状态不是"已回复"或"不再联系"
   - 从未被发送过（查 S.sendRecords）

2. 按品类分组（byCat）：
   - outdoor_knives / kitchen_knives / professional_scissors / kitchen_accessories

3. 每组按 leadScore 降序排列

4. 轮询选取（round-robin）：
   - 循环4个品类，每次从每组取1个
   - 直到取满15个或某组耗尽
   - 每个任务分配邮箱账户（按任务索引轮询可用账户）

5. 任务状态机：
   pending → sent（用户手动确认）→ 创建跟进提醒
   pending → skipped（用户跳过）
   pending → replaced（用户替换为同品类下一个客户）
```
